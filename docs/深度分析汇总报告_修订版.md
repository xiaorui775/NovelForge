## 2. 面向新手用户的定位修正

### 2.1 当前产品的「新手不友好」问题

NovelForge 当前有 **22 个功能模块**，对无写作经验的用户来说：

| 问题 | 影响 | 解决方向 |
|------|------|----------|
| 功能过多 | 新手不知道从哪里开始 | 全部保留，**用户主动触发调用** |
| 专业术语 | "伏笔追踪""一致性检查"等术语理解困难 | Chat 用自然语言解释，**用户主动调用** |
| 缺乏引导 | 没有从 0 到 1 的新手向导 | AI 辅助生成框架，**用户随时主动触发** |
| 设置门槛 | 模型配置、Prompt 模板等前置要求高 | 开箱即用预设，**随时主动调用** |

> **核心原则**：
> - ✅ 全部 22 个功能保留并可见
> - ✅ Chat 助手是**被动响应**工具：用户触发后调用功能
> - ❌ 不是「AI 主动弹窗提示」（打扰写作）
> - ❌ 不是「减少功能让新手少学」

### 2.2 正确的交互方式：用户主动触发

**AI 被动响应，用户主动触发**：

```
用户在写小说...          用户主动触发
     ↓                          ↓
需要检查一致性时         → 用户问 Chat:"帮我检查角色一致性" → AI 执行
角色设定有变化           → 用户问 Chat:"帮我记录角色更新" → AI 执行
想埋伏笔               → 用户问 Chat:"这个线索适合埋伏笔吗？" → AI 建议
完成 5 章后             → 用户点"生成质量报告"按钮 → AI 执行
写作遇到瓶颈            → 用户问 Chat:"帮我出点灵感" → AI 建议
```

**关键方法**：
- **AI 被动响应** → 用户不开口，AI 不主动建议
- **用户主动触发** → 想用时随时调用，不想用时安静干活
- **界面按钮始终可用** → 随时可点，不需要通过 Chat

## 3. 代码质量审计权重调整

### 3.1 安全相关问题

#### 问题 1: 系统完全无认证

**原分析**: P0 — 立即修复
**修正后**: P1（个人使用场景下可简化）

原因为：个人单机使用时 `user_id` 不是立即必须的。但如果部署在局域网/VPS 上，应有基本认证。

建议方案：**简化认证** — 不需要完整的 JWT/OAuth2，只需可选密码保护：

```python
# backend/app/dependencies/auth.py
async def optional_auth(request: Request):
    """可选认证：未设置密码时允许匿名访问"""
    if not settings.ADMIN_PASSWORD:
        return {"anonymous": True}
    # 检查请求头或 cookie 中的认证
    # ...
```

#### 问题 3: CORS 允许 `*`

**原分析**: P0 — 安全风险高
**修正后**: P2（个人使用时前后端通常同源，但部署在局域网时需要）

建议：提供配置项让用户自行设置 `CORS_ORIGINS`

### 5.5 为什么不是「减少功能」

| 对比维度 | 「减少功能」方案 | **「用户主动触发」方案**（正确方向）|
|---|---|---|
| **理念** | 功能多 = 负担 → 隐藏 | **功能多 = 帮助多 → 全部保留** |
| **用户操作** | 需要学会每个功能 | **想用就用，不想用就写** |
| **新手体验** | 功能少了，帮助也少了 | **功能全，自己随时调用** |
| **专家用户** | 找不到高级功能 | **全部功能始终可见** |
| **学习成本** | 需要学习功能名称和用法 | **自然语言即可调用** |

**核心认知转变**：
- 写作新手不是怕"功能多"，而是怕"写不出来"
- 功能多 = AI 能帮的地方多 = 写作负担更轻
- 关键是**用户想用时随时调用**，不是**AI 主动打扰**
- AI 被动响应，用户主动触发，不干扰创作节奏
